# Curion - 合成・地域限定・P2P交換システム設計

## 1. 合成システム（Synthesis System）

### コンセプト
**「現実世界と似た、直感的な合成」**
- 自然な組み合わせで新しいキュリオンが生まれる
- 意外な発見がある（錬金術的）
- 合成でしか手に入らないレアキュリオン

### 合成の基本ルール

#### レシピタイプ

**1. 直感的な合成（Intuitive）**
```
水 + 火 → 蒸気
土 + 水 → 泥
木 + 火 → 炭
金 + 銀 → 合金
赤 + 青 → 紫
```

**2. 概念的な合成（Conceptual）**
```
夢 + 光 → 希望
影 + 闇 → 絶望
星 + 月 → 宇宙
```

**3. 生物的な合成（Biological）**
```
狼 + 月 → 月光狼（レア）
龍 + 火 → 炎龍（レジェンド）
鳳凰 + 氷 → 氷鳳凰（レジェンド）
```

**4. 料理系合成（Cooking）**
```
米 + 火 → ご飯
魚 + 火 → 焼き魚
肉 + 火 → ステーキ
米 + 魚 + 海苔 → 寿司
小麦 + 卵 + 砂糖 → ケーキ
野菜 + 火 + 塩 → スープ
```

**5. 抽象概念合成（Abstract）**
```
愛 + 美 → 美愛（合成限定）
自由 + 勇気 → 解放
希望 + 光 → 明日
絶望 + 闇 → 虚無
正義 + 剣 → 聖剣
知恵 + 本 → 賢者の書
```

**6. ごった煮合成（Chaos Mix）**
```
猫 + 愛 → 愛猫（ペット）
料理 + 芸術 → 美食
音楽 + 数学 → ハーモニー
科学 + 魔法 → 錬金術
時間 + 空間 → 宇宙
生 + 死 → 輪廻
```

**7. 複雑な合成（Advanced）**
```
水 + 土 + 種 → 植物
火 + 土 + 金 → 剣
光 + 闇 + 魂 → 陰陽（合成限定レジェンド）
材料 + 火 + 愛 → 愛情料理（合成限定）
```

### 合成限定キュリオン

通常のGUID生成では絶対に出ない特別なキュリオン：

**レア合成限定**
- 月光狼（狼 + 月）
- 炎獅子（獅子 + 火）
- 氷鳳凰（鳳凰 + 氷）
- 雷麒麟（麒麟 + 雷）

**エピック合成限定**
- 虹龍（龍 + 虹）
- 星海（海 + 星）
- 夢幻蝶（蝶 + 夢）

**レジェンド合成限定**
- 創世龍（火 + 水 + 土 + 風 + 光 + 闇）
- 究極の無（全てのキュリオン）
- 時空の支配者（時 + 空 + 運命）

## 2. 地域限定キュリオンシステム

### コンセプト
**「旅の楽しみと交換の活性化」**
- 各国・各地域に固有のキュリオン
- その場所でしか手に入らない
- 地域限定 + 合成限定の超レアも存在

### 地域区分

**日本地域**
- 桜、富士山、侍、忍者、相撲、芸者、和菓子
- 合成限定: 桜吹雪（桜 + 風）

**中国地域**
- 龍、麒麟、パンダ、万里の長城、茶、餃子
- 合成限定: 五爪金龍（龍 + 金 + 皇帝）

**ヨーロッパ地域**
- 騎士、城、ワイン、チーズ、バラ、ゴシック
- 合成限定: 聖剣（剣 + 光 + 聖）

**アメリカ地域**
- イーグル、バイソン、自由の女神、ハンバーガー
- 合成限定: 星条旗（星 + 縞 + 自由）

**アフリカ地域**
- ライオン、象、キリン、サバンナ、バオバブ
- 合成限定: 大地の王（ライオン + 太陽 + サバンナ）

**オセアニア地域**
- カンガルー、コアラ、珊瑚礁、ボンダイ
- 合成限定: 珊瑚の守護者（珊瑚 + 海 + 魂）

**南米地域**
- ジャガー、アマゾン、インカ、コンドル
- 合成限定: 太陽神（太陽 + ジャガー + 金）

### 位置情報連携

```rust
struct RegionalCurion {

    ExclusiveToRegion,  // その地域でのみ入手可能
```

### 位置情報取得方法

**プライバシー重視**
- GPSではなく、IPアドレスベースの大まかな地域判定
- ユーザーが手動で地域を設定可能
- VPN使用時も考慮

## 3. P2P交換システム（Nostr-like）

### コンセプト
**「分散型・売買禁止・同時プレイヤー同士の直接交換」**
- 中央サーバー不要
- Nostr/Torrentのようなピアツーピア
- 金銭取引は一切なし、物々交換のみ
- リアルタイムでオンラインの相手とマッチング

### アーキテクチャ

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│ Player A│◄───►│ Relay 1 │◄───►│ Player B│
└─────────┘     └─────────┘     └─────────┘
     ▲               ▲                ▲
     │               │                │
     └───────────────┼────────────────┘
                     │
                ┌─────────┐
                │ Relay 2 │
                └─────────┘
```

### Nostr的な仕組み

**リレーサーバー（Relay）**
- 複数の公開リレーサーバー
- 誰でもリレーサーバーを立てられる
- メッセージの一時中継のみ（保存しない）

**イベント（Event）**
```json
{
  "kind": 30000,  // Curion交換リクエスト
  "pubkey": "公開鍵",
  "created_at": 1699999999,
  "tags": [
    ["offer", "龍"],
    ["want", "鳳凰"],
    ["region", "Japan"]
  ],
  "content": "龍と鳳凰を交換してくれる方募集！",
  "sig": "署名"
}
```

### 交換フロー

1. **交換リクエスト作成**
   ```
   Player A: 「龍」を出して「鳳凰」が欲しい
   → リレーにイベント発行
   ```

2. **マッチング**
   ```
   Player B: 「鳳凰」を持っていて「龍」が欲しい
   → リレーでPlayer Aのリクエストを発見
   → 交換申し込み
   ```

3. **交渉（オプション）**
   ```
   暗号化されたDMで交渉
   「龍1体 vs 鳳凰1体でOK？」
   「OK！」
   ```

4. **交換実行**
   ```
   両者が同意
   → スマートコントラクト的に同時交換
   → 互いのキュリオンが入れ替わる
   ```

5. **検証**
   ```
   交換完了イベントを発行
   → 両者のコレクションを更新
   → 不正がないか相互検証
   ```


## 4. 技術スタック

### P2P通信

**Nostr互換プロトコル**
```rust
// nostr-sdk クレートを使用
use nostr_sdk::prelude::*;

struct CurionRelay {
    client: Client,
    relays: Vec<String>,
}

impl CurionRelay {
    async fn publish_trade_offer(&self, offer: TradeOffer) -> Result<()> {
        let event = EventBuilder::new(
            Kind::Custom(30000),
            offer.to_json(),
            &[
                Tag::Generic(
                    TagKind::Custom("offer".into()),
                    vec![offer.offering[0].noun.clone()]
                ),
                // ...
            ]
        ).to_event(&self.keys)?;

        self.client.send_event(event).await?;
        Ok(())
    }
}
```

### リレーサーバー候補
- 公式リレー: `wss://relay.curion.app`
- 地域別リレー: `wss://relay-jp.curion.app`
- コミュニティリレー: 誰でも立てられる

### セキュリティ

**所有証明**
```rust
struct CurionOwnership {
    curion_id: String,
    owner_pubkey: String,
    signature: String,  // 秘密鍵で署名
    timestamp: DateTime<Utc>,
}

// 交換時の検証
fn verify_ownership(curion: &Curion, proof: &CurionOwnership) -> bool {
    verify_signature(
        &proof.owner_pubkey,
        &proof.signature,
        &curion.id
    )
}
```

**不正防止**
- 二重交換の防止（ブロックチェーン的な履歴管理）
- タイムスタンプ検証
- 両者の合意署名必須
